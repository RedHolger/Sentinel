## 1. Overview & Architectural Role

Stage 06 introduces a deterministic behavioral regression evaluator that tests the end-to-end vibration processing pipeline against explicitly synthetic scenarios with independently authored expectations.

```
┌─────────────────────────────────────────────────────────────┐
│ Suite Manifest (suite.json)                                │
│ - schema_version: "1.0.0"                                  │
│ - suite_id, evaluation_scope, description                  │
│ - cases: [Case 1, Case 2, ..., Case N]                     │
└──────────────────────────────┬──────────────────────────────┘
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
┌──────────────────────────────┐    ┌─────────────────────────┐
│ Input Artifacts (Relative)   │    │ Authored Expectations   │
│ - CSV file (raw bytes hash)  │    │ - Scope (window/env)    │
│ - Metadata JSON (provenance) │    │ - Window boundaries     │
│ - Configuration JSON         │    │ - Outcomes & reasons    │
└──────────────┬───────────────┘    └─────────────┬───────────┘
               │                                  │
               ▼                                  │
┌──────────────────────────────┐                  │
│ Ingestion & Evaluation       │                  │
│ - Single-read SHA-256 hashes │                  │
│ - Provenance must be synthetic                  │
│ - load_vibration_csv         │                  │
│ - evaluate_rms_threshold     │                  │
└──────────────┬───────────────┘                  │
               │                                  │
               ▼                                  ▼
┌─────────────────────────────────────────────────────────────┐
│ Comparison & Honest Accounting Engine                       │
│ - Case Status: MATCH, MISMATCH, or ERROR                    │
│ - Input errors never dropped from denominators              │
│ - Reconciled summary counts & decision totals               │
│ - No accuracy/precision/recall or fault-truth claims        │
│ - Bound to suite_sha256 and input file SHA-256 digests      │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│ CLI Output & Exit Semantics                                 │
│ - All cases MATCH  ─────────> Exit 0 (status: "PASS")       │
│ - Any MISMATCH or ERROR ────> Exit 1 (status: "FAIL")       │
│ - Malformed suite manifest -> Exit 2 (stderr diagnostic)    │
│ - Legacy evaluate (no suite)-> Preserved exit 1 NOT_IMPL    │
└─────────────────────────────────────────────────────────────┘
```

### Invariant & Boundary Commitments:
1. **Behavioral Regression Only (Not Diagnostic Accuracy):**
   - The evaluator verifies software pipeline behavior against declared synthetic expectations.
   - It does **not** measure diagnostic accuracy, precision, recall, or statistical confidence.
   - An all-abstention suite must never be described as perfect accuracy.
   - Expectations are authored independently; they are never generated by calling the detector under test.
2. **Relative Path Resolution:**
   - Paths inside the suite manifest are resolved relative to the directory containing the suite manifest file, guaranteeing portability across working directories.
3. **Synthetic Provenance Mandate:**
   - The loaded recording's `provenance` must be `"synthetic"`. Any case with `"recorded"` provenance is flagged as an `ERROR`.
4. **Honest Error Denominators:**
   - Input, read, digest, configuration, or provenance failures produce `ERROR`.
   - The evaluator continues processing subsequent independent cases.
   - Errors are never silently dropped from total case counts.
5. **Byte Hash Binding:**
   - The evaluation report binds to the raw byte SHA-256 of the suite manifest and the raw byte SHA-256 of all input files parsed in that single read. Files are never reread after execution to manufacture hashes.
6. **Scaffold & Prior CLI Preservation:**
   - `adi-portfolio evaluate` without `--suite` preserves baseline scaffold behavior (`NOT_IMPLEMENTED`, exit 1).
   - `adi-portfolio analyze`, `demo`, and `benchmark` are completely preserved.

## 2. Suite Manifest Schema (`ScenarioSuiteV1`)

A suite manifest is a strict UTF-8 JSON object adhering to:

```json
{
  "schema_version": "1.0.0",
  "suite_id": "suite_synthetic_baseline_01",
  "evaluation_scope": "synthetic_behavioral_regression",
  "description": "Baseline behavioral regression suite covering normal, anomalous, saturated, and mismatch conditions.",
  "cases": [
    {
      "case_id": "case_01_normal_window",
      "description": "Single-channel normal window strictly below threshold",
      "csv_path": "data/normal.csv",
      "metadata_path": "data/metadata_1000hz.json",
      "config_path": "data/config_thresh2.json",
      "expected_csv_sha256": "3e72ef8fd0f9d6310e86c26f1d5885d5a576901a1ce5272519406af4f0e8b0d1",
      "expected_result": {
        "scope": "window",
        "windows": [
          {
            "window_index": 0,
            "start_sample": 0,
            "end_sample": 5,
            "outcome": "NORMAL",
            "quality_status": "PASS",
            "reason_codes": []
          }
        ]
      }
    },
    {
      "case_id": "case_02_recording_envelope_mismatch",
      "description": "Recording-level sample rate mismatch producing abstention",
      "csv_path": "data/normal.csv",
      "metadata_path": "data/metadata_500hz.json",
      "config_path": "data/config_thresh2.json",
      "expected_csv_sha256": "3e72ef8fd0f9d6310e86c26f1d5885d5a576901a1ce5272519406af4f0e8b0d1",
      "expected_result": {
        "scope": "recording_envelope",
        "outcome": "INSUFFICIENT_EVIDENCE",
        "quality_status": "FAIL",
        "reason_codes": ["SAMPLE_RATE_MISMATCH"]
      }
    }
  ]
}
```

### Strict Syntax Rules:
- Rejects duplicate keys (via `object_pairs_hook`).
- Rejects nonstandard constants (`NaN`, `Infinity`).
- Rejects unknown fields at suite and case levels.
- Rejects duplicate `case_id` values.
- Rejects empty `cases` list.

## 3. Comparison & Accounting Rules

For each case in `cases`:
1. **Input Snapshot:**
   - Read CSV file bytes once $\implies$ compute `csv_sha256`. Check against `expected_csv_sha256`.
   - Read metadata JSON bytes once $\implies$ compute `metadata_sha256`. Parse strict JSON.
   - Read config JSON bytes once $\implies$ compute `config_sha256`. Parse strict JSON.
   - If any file missing, unreadable, or invalid JSON $\implies$ status `ERROR`.
2. **Provenance Check:**
   - Enforce `metadata.get("provenance") == "synthetic"`. If `"recorded"` $\implies$ status `ERROR`.
3. **Pipeline Ingestion & Detector Execution:**
   - Ingest via `load_vibration_csv`.
   - Evaluate via `evaluate_rms_threshold`.
   - If ingestion or detector raises expected exception $\implies$ status `ERROR`.
4. **Comparison against `expected_result`:**
   - Check scope match:
     - Envelope abstention (`status == "INSUFFICIENT_EVIDENCE"` and `window_boundaries == []`) $\implies$ actual scope `"recording_envelope"`.
     - Window extraction (`status == "COMPLETED"`) $\implies$ actual scope `"window"`.
   - If scope mismatches $\implies$ status `MISMATCH`.
   - If scope matches:
     - For `"recording_envelope"`:
       Compare `outcome`, `quality_status`, and `sorted(reason_codes)`.
       If all match $\implies$ `MATCH`; otherwise `MISMATCH` with discrepancy details.
     - For `"window"`:
       Verify window count matches expected.
       For each window, compare `window_index`, `start_sample`, `end_sample`, `outcome`, `quality_status`, and `sorted(reason_codes)`.
       If all match $\implies$ `MATCH`; otherwise `MISMATCH` with discrepancy details.
5. **Reconciliation Invariants:**
   - `total_cases == matched_cases + mismatched_cases + error_cases`
   - Actual decisions are summed across all evaluated cases and categorized by outcome and scope.

## 5. CLI Command & Exit Code Specification

### Command:
```text
adi-portfolio evaluate [--suite PATH] [--trials TRIALS]
```

### Exit Semantics:
- **`adi-portfolio evaluate --suite <PATH>`:**
  - `Exit 0`: All cases in suite evaluated to `MATCH` (`status: "PASS"`). Emits evaluation report JSON to `stdout`.
  - `Exit 1`: One or more cases evaluated to `MISMATCH` or `ERROR` (`status: "FAIL"`). Emits evaluation report JSON to `stdout`.
  - `Exit 2`: Malformed, unreadable, or invalid suite manifest file (missing file, duplicate keys, nonstandard constants, non-object, invalid schema, duplicate case IDs, or missing required CLI option value). Emits concise diagnostic to `stderr`; `stdout` is empty.
- **`adi-portfolio evaluate` (without `--suite`):**
  - `Exit 1`: Preserved baseline scaffold output (`status: "NOT_IMPLEMENTED"`, `hardware_status: "UNVERIFIED"`).

## 6. Synthetic Fixtures Specification

Checked-in test fixtures will be located under `adi-app/tests/fixtures/scenarios/`:
1. `normal_single_window`: RMS strictly below threshold $\implies$ `NORMAL`.
2. `anomaly_single_window`: RMS strictly above threshold $\implies$ `ANOMALY`.
3. `threshold_equality_window`: RMS exactly equals threshold $\implies$ `ANOMALY`.
4. `saturation_single_window`: $|x| \ge \text{full\_scale}$ $\implies$ `INSUFFICIENT_EVIDENCE` (`SENSOR_SATURATION_POSSIBLE`).
5. `mixed_multi_window`: Window 0 NORMAL, Window 1 Saturated, Window 2 ANOMALY.
6. `recording_envelope_mismatch`: Sample rate mismatch $\implies$ recording-level abstention (`SAMPLE_RATE_MISMATCH`).
7. `insufficient_recording_length`: Recording samples < `window_size` $\implies$ recording-level abstention (`INSUFFICIENT_RECORDING_LENGTH`).

All fixtures will have explicit static analytical expectations authored independently. All metadata files will enforce `provenance: "synthetic"`.
